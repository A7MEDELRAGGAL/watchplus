1. فكرة المشروع

نعمل Anime Scraper & Importer مستقل، وظيفته:

المواقع المصدر → Scraper → توحيد البيانات → قاعدة البيانات → API/Import → موقعك

يعني بدل ما كل موقع يكون له شكل مختلف، البرنامج يحول البيانات كلها إلى شكل موحد يناسب موقعك.

مثلاً:

Anime

 │    │    │    └── Server 3
 │    │    ├── Episode 2
 │    │    └── ...
 │    └── Season 2
 └── ...

5. السيرفرات

وده الجزء اللي أنت مركز عليه.

لكل حلقة يكون عندنا:

Episode
 └── Servers
      ├── Server A
      ├── Server B
      ├── Server C
      └── ...

مثلاً:

{
  "name": "Episode 12",
  "servers": [
    {
      "name": "Mega",
      "url": "..."
    },
    {
      "name": "Google",
      "url": "..."
    }
  ]
}

والبرنامج لا يفترض أسماء السيرفرات مسبقًا.

لو الصفحة فيها:

Mega
Google
Stream
Server 4

يقدر الـAdapter الخاص بالموقع يستخرجهم حسب طريقة بناء الموقع.

6. الفرق المهم في الروابط

هنفصل بين:

Episode Page URL

رابط صفحة الحلقة نفسها:

https://example.com/anime/episode-12

وبين:

Server URL

الرابط الذي توفره الصفحة للسيرفر:

https://mega.example/...

أو:

https://google.example/...

وبالتالي موقعك يقدر يعرض:

Episode 12

[Server 1]
[Server 2]
[Server 3]

بدون خلط رابط صفحة الحلقة مع رابط السيرفر.

7. استخراج الرابط المباشر

هنعمل في النظام 3 مستويات:

page_url
server_url
direct_url

مثلاً:

{
  "page_url": "...",
  "server_url": "...",
  "direct_url": null
}

لو الموقع نفسه يوفر رابط مباشر علني، ممكن نخزنه.

أما لو السيرفر يحتاج تجاوز DRM أو CAPTCHA أو نظام حماية أو توقيع مؤقت للوصول للرابط النهائي، فالبرنامج ما يحاولش كسر الحماية.

وده كمان أفضل هندسيًا، لأن بعض الروابط المباشرة بتكون مؤقتة وتنتهي بعد فترة.

9. نظام الـAdapters

دي أهم نقطة في المشروع.

مش هنعمل:

if site == "site1":
   ...
elif site == "site2":
   ...
elif site == "site3":
   ...

لأن ده هيتحول لفوضى.

نعمل:

BaseScraper
     │
     ├── AnimeWitScraper
     ├── AnimeLuxScraper
     ├── Site3Scraper
     └── Site4Scraper

كل موقع له Adapter مستقل.

لو موقع غير تصميمه، نعدل Adapter الخاص به فقط.

13. منع التكرار

دي مهمة جدًا.

لو شغلت الـScraper اليوم:

Anime A
Episode 1

وبعدين شغلته بكرة، مش هيعمل:

Episode 1
Episode 1

هنستخدم IDs وUnique Constraints.

مثلاً:

source + source_id

للأنمي.

و:

anime_id + season_number + episode_number

للحلقة.

والسيرفر:

episode_id + server_name + server_url
14. تحديث البيانات

لو الأنمي موجود بالفعل:

INSERT

مش دايمًا.

النظام يقرر:

New → INSERT

Existing + changed → UPDATE

Existing + unchanged → SKIP

وده يقلل الضغط على المواقع المصدر.

15. نظام الـRetry

لو الطلب فشل:

Attempt 1
Attempt 2
Attempt 3

مع تأخير بين المحاولات.

مثلاً:

1 sec
2 sec
4 sec

وبعدها يسجل الخطأ بدل ما البرنامج كله يقع.

16. Rate Limiting

مش هنضرب الموقع بآلاف الطلبات في الثانية.

مثلاً:

REQUEST_DELAY=1.0
MAX_CONCURRENT_REQUESTS=3

والقيم تتغير من الإعدادات.

بدل ما كل تجربة تضرب الموقع من جديد.

مثلاً:

data/cache/

30. Multi-source

لو نفس الأنمي موجود في موقعين:

Source A
Source B

نقدر نخزن المصدرين بدل ما نكرر الأنمي.

مثلاً:

Anime
 ├── Source A
 └── Source B

وبالتالي موقعك يقدر يكون عنده أكثر من مصدر.

31. Source Priority

ممكن نحدد:

Source A = priority 1
Source B = priority 2
Source C = priority 3

لكن ده مش معناه ترتيب جودة؛ مجرد أولوية تقنية عند اختيار مصدر افتراضي.

32. Data Normalization

مثلاً موقع يقول:

Ep 01

وموقع تاني:

Episode 1

وموقع ثالث:

الحلقة ١

الـNormalizer يحولها إلى:

episode_number = 1

ونفس الكلام للمواسم والأسماء والتصنيفات.

39. أهم نقطة: الموقع بتاعك

مش عايز أخلي الـScraper مربوط بشكل صلب بموقعك.

نخليه:

                 ┌── Source Adapter 1
                 ├── Source Adapter 2
Sources ────────┤
                 └── Source Adapter 3
                         ↓
                  Normalized Data
                         ↓
                     Database
                         ↓
                       API
                         ↓
                   Your Website

كده لو غيرت موقعك من React إلى Next.js أو أي حاجة تانية، الـScraper نفسه مش محتاج يتغير.

40. الـWorkflow الكامل

لما تعمل:

python main.py scrape

يعمل:

1. Load configuration
        ↓
2. Load enabled sources
        ↓
3. Discover anime
        ↓
4. Open anime page
        ↓
5. Extract metadata
        ↓
6. Find seasons
        ↓
7. Find episodes
        ↓
8. Open each episode
        ↓
9. Extract available servers
        ↓
10. Normalize data
        ↓
11. Check duplicates
        ↓
12. Insert/update database
        ↓
13. Log result
        ↓
14. Continue
